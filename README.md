# Bug Predict

## 1. Overview
Bug Predict is an AI-powered software risk and bug prediction platform. It helps developers, engineering managers, and technical leads understand where their software may be at risk before problems reach users.

## 2. Problem Statement
Modern software engineering produces massive codebases with complex logic. It is difficult to statically predict where bugs are most likely to occur. Traditional tools rely on manual review or basic linting, lacking predictive historical insight.

## 3. Key Features
- **Project Health Overview**: Fast, reliable insights into your public GitHub repositories.
- **Risk Prediction**: Machine learning predicts the likelihood of defects based on codebase complexity, churn, and repository history.
- **AI Explanations**: Plain English explanations generated by Google Gemini to clarify why an area is risky and what to do about it.
- **Actionable Recommendations**: Test suggestions and immediate next steps.
- **Enterprise-Grade UI**: A premium, clean, and accessible dashboard.
- **Downloadable PDF Reports**: Shareable executive summaries and technical details.

## 4. How Bug Predict Works
Bug Predict fetches code directly from GitHub, computes static software metrics (like lines of code and cyclomatic complexity), feeds those metrics into a supervised Machine Learning model, and finally uses LLMs to interpret the results.

## 5. System Flow
`GitHub → Metrics → XGBoost → Risk Prediction → Gemini explanation flow`
1. Fetch file trees and commits via GitHub API.
2. Extract cyclomatic complexity, LOC, and churn.
3. Feed metrics into a trained XGBoost classifier.
4. Calculate a 0-100 risk probability.
5. Send high-risk snippets to Gemini for plain-English explanations.

## 6. Main Application Screens
- **Landing Page**: Marketing, features, and pricing.
- **Dashboard**: History of previous analyses.
- **Analysis Screen**: Interactive step-by-step progress of the repository scan.
- **Results Page**: File-by-file breakdown, high-level metrics, and PDF generation.

## 7. Technology Stack
- **Frontend**: Next.js 14+ (App Router), TypeScript, Tailwind CSS.
- **Backend**: Next.js API Routes + Python FastAPI.
- **Database**: Neon Serverless Postgres via Prisma ORM.
- **Authentication**: NextAuth.js (Credentials).
- **ML / AI**: XGBoost, Scikit-Learn, Google Gemini API.

## 8. Prerequisites
- Node.js (v18+)
- Python (v3.9+)
- A Neon Postgres database
- GitHub Personal Access Token
- Google Gemini API Key

## 9. Installation/Setup
1. Clone the repository.
2. Run `npm install` for frontend dependencies.
3. Navigate to `api/` and run `pip install -r requirements.txt`.
4. Copy `.env.example` to `.env`.

## 10. Environment Variables
Create a `.env` file with the following keys (do not commit real secrets!):
```env
DATABASE_URL=
AUTH_SECRET=
GITHUB_TOKEN=
GEMINI_API_KEY=
NEXT_PUBLIC_APP_URL=
```

## 11. Local Development
1. Ensure your `.env` is populated.
2. Run Prisma migrations: `npx prisma db push`.
3. Start the application: `npm run dev` (this starts both Next.js and the Python API on Vercel dev).
Alternatively, start Python manually: `uv run uvicorn api.index:app --port 5328`.

## 12. Running Tests
- Frontend tests: `npm run test`
- ML pipeline tests: `python -m pytest`

## 13. Basic Usage
1. Sign up or log in.
2. Paste a GitHub repository URL into the analysis input.
3. Wait for the engine to fetch, process, and analyze the files.
4. Review the results dashboard or download the PDF risk report.

## 14. Deployment
Designed for Vercel:
1. Connect GitHub to Vercel.
2. Add all Environment Variables in Vercel settings.
3. Vercel automatically builds `/api` using `requirements.txt`.
4. Run Prisma db push to Neon.

## 15. Limitations
- Python Serverless functions on Vercel free tier have a 10s timeout, limiting large repository scans.
- Only public GitHub repositories are officially supported.
- Features are mapped approximations to Halstead metrics.

## 16. Future Improvements
- Background task queues (Celery/Redis) to bypass the 10s timeout.
- Private repository support via OAuth.
- Integration with CI/CD pipelines (GitHub Actions).
